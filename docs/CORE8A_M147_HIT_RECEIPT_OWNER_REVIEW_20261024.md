## Proposed wire registry — **NOT ALLOCATED**

This is on existing original **v1 reliable gameplay** framing over one authenticated WebTransport **bidirectional** stream with existing u16LE frame-length prefix. It is neither the v2 source0/KeyE1 `02 11` event/`02 12` ACK family nor optional chat `0x31`–`0x33`; no second QUIC connection, no datagram receipt, no WebSocket fallback.

| Server/client frame | Status | Layout |
|---|---|---|
| v1 HIT_RECEIPT (proposed type **5 / 0x05**) | dormant exact donor fixture | **28 B**: `u8 version=1`, `u8 type=5`, `u16LE reserved=0`, `u32LE recipient-local delivery sequence`, `u32LE World tick`, `u32LE attacker`, `u32LE victim`, `f32LE damage`, `f32LE remaining victim HP` |
| v1 HIT_CONTROL (proposed type **6 / 0x06**) | new pure Rust/JS offline review fixture | **32 B**: `u8 version=1`, `u8 type=6`, `u8 op`, `u8 reserved=0`, `u32LE cursor`, **16B opaque current HIT lease token**, `u32LE aux`, `u32LE reserved=0` |

32B operations: `1 CLIENT_HELLO` only all-zero token/cursor/aux; `2 SERVER_GRANT` nonzero secure **server-minted** token, cursor 0 and aux allowed in 1–64 pending cap; `3 CLIENT_ACK` current token + next contiguous locally validated/presented sequence, aux0; `4 SERVER_GAP` current token, cursor first missing, aux oldest available; `5 SERVER_RETIRED` current token, cursor/aux reason; `6 CLIENT_NACK` current token + next missing, aux0. Unknown type/op, wrong length/version, nonzero reserved, zero lease token for non-HELLO, wrong capacity/aux fail closed. The 28B HIT has **no token field**: the receiver MUST bind it to the specific current *authenticated* WebTransport stream object that carries it and a previously authenticated GRANT; never feed arbitrary byte arrays to a UI. JS offline helper's object identity is a dependency injected from the eventual TLS transport, NOT proof of authentication by itself.

Rust/JS fixed byte vector for 32B `SERVER_GRANT`: `01 06 02 00 00 00 00 00 01 02 03 04 05 06 07 08 09 0a 0b 0c 0d 0e 0f 10 40 00 00 00 00 00 00 00`. Existing Rust/JS 28B HIT donor vector: attacker2 to victim1 actual 34HP / target66 with its donor server tick and sequence. No single byte of type5 or type6 is registered in `PACKET_TYPE` or sent by the actual `server/src/main.rs` on this draft.

## Authority, session and replay (agreed proposal **subject to Main0/Core8C signoff**)

1. Only original 60Hz `World.step_into(events)` committed `CombatEvent::Hit {attacker,target,damage,hp}` under game state lock may create the canonical HIT. An `02 12 ACCEPTED` gesture ACK, a v1 input ACK, HP delta, native stdout, LMB press, parry, block or miss cannot create or justify HIT credit. At commit capture canonical (server boot nonce, actor World generation, World tick, within-tick event ordinal) and immutable originating actor/target incarnations.
2. Core8B/8C auth must resolve attacker and victim **at commit**, then bind a recipient projection to current verified TLS QUIC connection's allocated player ID, server lease_epoch and death/respawn incarnation. Numeric ID alone is insufficient after actor reuse. One locally verified attacker gets `hit-confirm`; victim gets `damage-taken`; uninvolved spectator gets **no** attacker credit or hit-confirm (may get neutral HP snapshot).
3. Project the donor global `HitReceiptJournal` into a **per-recipient contiguous u32 delivery sequence**; the global journal cursor may skip other people's HITs, so its global sequence is **not** suitable directly for application contiguous ACK. New connection/actor incarnation starts at **current** event tail, never inherits past attacker credit. On replacement, old token, cursor, delayed UI callback and byte replay must be rejected. Zero/near-wrap expiry retires lease before u32 wrap.
4. The receiver `createProposedHitInbox` is an **unwired review helper**. It checks exact injected current-transport object identity, nonzero verified actor and current GRANT before accepting strict 28B HIT. It presents only the bound actor role synchronously and produces a proposed next-contiguous ACK **after** accepted presentation enqueue. Same-sequence duplicate produces ACK again but **never** another hit-confirm. Future seq produces NACK expected, withholds credit until contiguous recovery; foreign third-party actor, wrong transport or old actor after retire is refused. GAP marks a blocked/unverified state and invokes an explicit callback, never positive credit. Callback error prevents cursor advance/ACK. A separate safe writer must actually transmit the returned control frame after Main approval.
5. Server TODO **not present in this draft**: consume `_reliable_recv` as bounded, authenticated, strict HELLO/ACK/NACK; mint token with OS CSPRNG; gate capability/ownership to server session/grant; read one World-generated event source (not duplicate combat systems), implement <=256 global history and <=64 recipient pending, fair reliable queue under max512, byte-exact unACKed same-lease retries and explicit overflow GAP, close/retire on transport death and stale session. The existing reliable channel capacity1 and try_enqueue **are not application ACKs**. Reliable sends must never block original 60Hz World; datagram mobility and Combat keep priority.
6. UI10/Combat4/Sound5 TODO **not present**: consume only verified role messages, stop `collectEntityEvents` from awarding `hit-confirm` on anonymous peer HP deltas after actual receipt path is working. Preserve victim HP snapshot and neutral effects. No actor credit from snapshot latency or source fiction.
