## Engineering dependency resolved as code for review, not as actual live authentication

The existing [#453](https://github.com/tehki/myaso/pull/453) global 256-HIT bounded `HitReceiptJournal` gives global u32 event sequences. `read_for_actor` skips unauthorized hits, so its global cursor **cannot** be used as the contiguous `createProposedHitInbox` cursor. Otherwise actor2 could receive only global seq1 after actor3 hits actor4 at seq0, NACK permanently for missing 0, and never display their actually earned HIT.

New `server/src/combat_hit_delivery_proposal.rs` defines `ProposedRecipientHitDelivery` and immutable `ActorIncarnation {boot u128, world_generation u64, net_id u32, actor_generation u64, lease_epoch u64}`. These are **server-side evidence fields only**: the current public Rust server has no persistent account identity or approved HIT lifecycle mint. Actual Core8C must supply session binding from original admitted QUIC/World; the standalone API does not authenticate caller-provided `ActorIncarnation`. It accepts a 16B opaque token only from an externally authenticated caller, never mints or exposes one, and rejects zero token, zero incarnation fields, wrong scopes, wrong lease token, wrong actor-generation/session-epoch.

`CommittedHitIdentity {server_tick, within_tick_ordinal, attacker:ActorIncarnation, victim:ActorIncarnation}` must be captured by the original 60Hz World **under the same state mutex and on the actual `CombatEvent::Hit` tick**. The proposal validates event attacker/victim IDs against captured identities, their shared server boot+World generation, strictly increasing (tick, ordinal), and reuses `HitReceipt::from_combat_event`. The ordinal is a deterministic server-authoritative same-tick ordering key, not a client input tick or geometry claim. A separate mismatched/stale actor-life/boot is **not** entitled even if its numeric net ID is the same. For each relevant recipient, the seq counter begins at 0 and advances **only** on hits where the entire actor incarnation equals attacker or victim. Unrelated global hits still advance last World-key provenance but **not** local delivery seq, thus no phantom gaps.

Per actor+QUIC lease at most **64 pending** receipts. An overflow fails closed with terminal `PendingOverflow{first_missing}` and gapped flag; caller must send authenticated control GAP or close, not continue awarding credit. A sequence at `u32::MAX` refuses wrap (new authenticated lease required). Each pending packet must pass through **one** existing reliable framed writer, and the writer must call `mark_written(seq)` only AFTER a successful actual stream write, not when queued. Still, `mark_written` is **not client acceptance** and does not advance `acknowledged_next`. Client `CLIENT_ACK(next)` may advance cumulatively only up to last written contiguous seq, with exact active connection scope+nonzero 16B lease token; future, stale, foreign and unsent ACK are refused. Same next ACK is idempotent. Only byte-exact already-written, still-unACKed sequence may be replayed under same lease. Retire erases lease token and pending references; stale callbacks or numerical actor rebind are denied. The global 256-entry source may remain the canonical history; this bounded projection is a **separate per-recipient index**, not another gameplay authority.
