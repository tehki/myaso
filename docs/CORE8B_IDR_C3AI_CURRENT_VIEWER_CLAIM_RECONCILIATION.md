# Core 8B C3ai — current-viewer-only offline observer claim reconciliation

**Moon Games First Playable P0 / Main IDR #636, Core 8B #653. DRAFT, OFFLINE ONLY.** Child of [C3ah #688](https://github.com/tehki/myaso/pull/688). Zero network, production World/Combat/Physics, original Items/MYTX writer, MYID wire encoding, epoch format, DB migration or deployment changes.

## Why a durable receipt is not a current claim

A correctly fsynced `MYID` V1 historical `OfflineIdentityEvent::Claim` remains valid through a server restart, but it is **not** current observer knowledge just because the (observer, subject) tuple still exists on disk. A source may have disconnected and reconnected with a new authenticated `CharacterRecord.session_generation`, or changed disguises, and an old player connection/net slot may be reused. Old `observed_unverified_claim(observer,subject)` is now explicitly documented as **historical inspection only**: callers must not project it onto a browser or upgrade it to a real name.

## Minimal dormant read boundary

- `CanonicalIdrBridge::preflight_current_claim_read(observer, observer_lease, speaker, speaker_lease, SessionLeaseRegistry)` requires **both original canonical full-width u128 actors** be distinct, currently authenticated Core players with the exact current lease/generation in the bridge and committed lease registry. A Sentinel cannot forge a player view; a recycled connection number, disconnected source/viewer or old generation fails. Reads the current subject `presentation_epoch` from the server-owned in-memory `IdentityRegistry`; never accepts an arbitrary caller-supplied epoch as actual.
- `OfflineClaimJournal::read_claim_for_current_viewer(CurrentClaimRead)` first checks journal poison state and both actors' current lease/epoch, then local tombstones, then compares the historical observer+source claim's recorded source generation and appearance epoch to the *current* source. Any mismatch is **Unknown**, without rewriting history, advancing a journal sequence or manufacturing a new Verified witness. Output is only `CurrentClaimView::Unknown` or `CurrentClaimView::Claimed { display_claim }`, with **no Verified variant, canonical actor ID, private true name, item identity or controller-kind metadata**. Journal remains one exclusive local MYID writer. This function is read-only, O(log n) after the bridge's identity checks.
- If the *viewer* loses their authenticated lease, return a strict Untrusted error, **not** a stale claim. A new viewer with a different canonical ID always sees their own (usually Unknown) record, never another viewer's belief. A reconnected *speaker* retains prior historical data, but that record is Unknown until a newly committed claim at the new source generation appears. A server-owned appearance transition invalidates the old claim for live-view purposes before the historical journal is modified. Subject tombstone stays Unknown even across reopened journal recovery.

## Real negative tests

1. Two genuine Core player canonical IDs, one Sentinel and an independent third viewer. A current viewer sees Unknown until an unverified claim is durably committed, then Claimed for that viewer. Another viewer stays Unknown. Sentinel-origin viewer with an arbitrarily crafted Core lease is denied because its controller is server-side Sentinel. Reopen the fsynced journal: claim is still Claimed **only while both current leases remain valid**.
2. Reconnect the speaker under higher committed generation and different actual connection. Both the original now-stale speaker lease and a not-yet-rebound bridge are rejected. Rebinding the same canonical actor returns **Unknown**, even while `observed_unverified_claim` still contains the old event. Only a newly committed claim under the higher generation returns Claimed. Disconnect the viewer and its old lease cannot read.
3. Commit first claim, then advance the *server-owned* appearance epoch using a test-only trusted transition: old current-view becomes Unknown without altering history; new claim at correct epoch becomes Claimed. Persist a tombstone: current-view becomes Unknown and all claims disappear; repeat after closing/reopening the one local journal.

The original parent crash-after-fsync-before-ACK SIGKILL recovery, tampered MYID checksum, sequence-gap, protected-floor rollback and exact replay tests remain unchanged and must continue passing. **Historical receipts continue to exist but do not prove current actor identity.**

## Hard remaining trust boundaries

- The bridge's `IdentityRegistry` and lease high-water are **in-memory** and can themselves be rolled back independently of MYID. If **both** an old valid MYID prefix and canonical actor/lease state are restored, this read-only comparison alone cannot detect it. An externally protected monotonic store epoch/tombstone floor plus fsynced identity/appearance event chain is mandatory for production. A valid unkeyed checksum is not trusted anti-rollback.
- Sender and viewer may be distinct current actors but these APIs **do not prove** current World visibility or complete LOS, sender speech reach, server tick/zone, 8C/Physics witness list, or actor's actual history. Public 8A transport remains absent; never put full canonical IDs, true names/controller-kind or stale history on a client packet.
- **No Verified evidence opcode or cryptographic evidence authentication exists here.** Do not interpret a claimed label as verified truth. Reviewer of future combined IDR must decide what happens to valid knowledge across logout/reconnect under explicit gameplay policy; this slice conservatively requires the **speaker** to re-introduce after a newer session generation.
- First Playable Alpha still needs the real four-person same Greyhaven scene, four physical rack swords, a single epoch-fenced Core+Items custody writer, real authenticated pickup/drop/replication and armed/unarmed combat.
