# Core 8B C3ao — exact MYID history witness for independently protected recovery

**Project:** myaso.io / Moon Games. **Owner:** Core 8B, IDR #653. **Status:** DORMANT, offline Linux prototype; draft child of [C3an #739](https://github.com/tehki/myaso/pull/739). Combat Pre-Alpha #695 remains independent of this optional IDR program. Main #360 owns merge/release.

## The real rollback/fork gap

C3an pins startup lock, directory and recovery to one local inode; C3am pins publication to that directory; MYID V1 records enforce FNV, format, strict sequence and exact event IDs. But a **complete byte-valid older snapshot** can pass ordinary `open`. Even `open_with_minimum_head(root, floor)` is insufficient when two different histories have the **same head**: a local attacker can replace the text of a stored Unverified Claim with another equal-length, valid UTF-8 name, recompute unkeyed FNV and keep sequence, event ID and length unchanged. Both versions are internally coherent. A minimum numeric sequence alone does not identify the authentic historical contents.

## Scoped implementation (not a production trust anchor)

- Direct pinned dependency `ring = =0.17.14`, already present in the locked dependency graph via wtransport, now used directly to compute standard SHA-256; Cargo.lock only adds `ring` to `myaso-server`'s existing dependency list.
- `OfflineClaimJournal::offline_exact_history_witness()` yields `OfflineExactHistoryWitness { head: u64, sha256: [u8;32] }`. The digest domain is `MYID-V1-EXACT-HISTORY\0` + exact head as little-endian u64 + canonical 256-byte encoded V1 records in strictly ascending committed sequence. Reject poisoned writer, unexpected missing/duplicate order or replaced root/lock before/after digest. This is over the **actual already decoded and replay-validated** local records; no new on-disk event format, browser protocol, durable writer or global data layer.
- `OfflineClaimJournal::open_with_external_exact_history_witness(root, protected)` acquires and recovers through C3an's sole pinned journal lock, rejects any head below `protected.head` as `RollbackSuspected`, and rejects any different head or same-height SHA-256 history as `ExternalWitnessMismatch`. A longer local unapproved history also fails until the independent authority obtains and protects a new exact witness. This deliberate **exact** equality prevents quietly blessing extra events, but does not offer a scalable live attestation protocol or an atomic witness-outbox transaction.
- **Security trust is OUTSIDE this module.** The witness is a bare, unsigned SHA-256 descriptor; any untrusted caller may construct one. Its value is trustworthy ONLY if an independently trusted coordinator captured the authentic one and stored/attested it in an access-controlled monotonic system not rollbackable with these MYID files. SHA-256 is not a signature/MAC, and a checksum or a witness stored in the same directory is never anti-rollback. A malicious caller that supplies a digest computed from a forgery trivially passes. Never advertise the module as a production globally fenced identity authority.

## Real negative evidence

1. The real journal fsyncs a canonical Unverified Claim `Marta` at head1. The exact SHA-256 witness is reproducible, and a clean restart with that independently copied witness succeeds. An adversary rewrites that same numbered file's claimed name to `Tomas` (same byte length), recalculates the legacy FNV32, and keeps every other journal byte canonical. **Plain `open` succeeds and projects `Tomas`**. Its head remains 1, so a numeric floor of 1 would also pass. **The original externally retained exact SHA-256 witness denies it** with `ExternalWitnessMismatch`. A freshly forged witness computed from the attacker's rewritten store naturally succeeds, proving why the external witness must be authenticated independently.
2. Another real journal fsyncs event1, captures witness1, then fsyncs event2 and captures witness2. Exact-witness reopen with witness1 denies the **longer unapproved** local history, while witness2 accepts. Delete event2 to restore an internally valid earlier prefix: plain open succeeds with head1, but witness2 denies `RollbackSuspected`; old witness1 alone accepts. The authority must be responsible for supplying the most recent witness.
3. All original C3an tests remain: Linux pinned startup/recovery, final-component O_NOFOLLOW and nlink checks, pinned-dirfd creation/publish + no-overwrite, inode-split lock denial, real SIGKILL after fsync before observer ACK, canonical lease/presentation checks, tombstones, FNV corruption and old-valid-snapshot counterexample.
