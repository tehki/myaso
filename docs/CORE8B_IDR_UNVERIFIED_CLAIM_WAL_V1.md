# Core 8B — dormant MYID V1 observer-claim durability slice

**Main IDR #636 / Core8B assignment #653 / Moon Games First Playable P0.**
This is a narrowly scoped child of [canonical bridge #670](https://github.com/tehki/myaso/pull/670). The new `server/src/idr_claim_journal.rs` is an **OFFLINE LOCAL Unix prototype**. No running myaso server invokes its writer. No new live command, packet, database migration, authenticated remote request, item-ownership writer, true-name authority or actual identity verification exists in this PR.

## Implemented and why

- A separate *identity-knowledge* logical store with one POSIX advisory exclusive lock, owner-only local directory and per-event files, not a second ledger that owns swords. Each numbered `MYID` V1 event is precisely 256 bytes with fixed magic/version/reserved bytes, canonical nonzero u128 event and actor/observer IDs, record sequence, actor session generation and appearance epoch. Max 8192 historical events; UTF-8 claimed names bounded by dormant IDR validation. Immutable data staged with create-new owner-only permissions, fsynced, renamed to a canonical ordinal file and directory fsynced **before** returning a local receipt. Read-only ordered recovery rejects missing sequence, duplicate event ID, malformed UTF-8, invalid opcode/shape, reserved bytes and incorrect checksum. Orphan staging files are ignored. Loss or failure during publish poisons the in-memory writer rather than returning a fabricated success.
- **There is NO Verified opcode.** `OfflineIdentityEvent` admits *Unverified Claim* or *Trusted Offline Tombstone*, and not a browser-owned verification boolean. Before an unverified claim is appended, `CanonicalIdrBridge::preflight_offline_unverified_claim` requires a known receiver and the active actor's actual Core `CharacterId(u128)`, still-current `SessionLease` and exact committed generation. Network ID/appearance/item ID is never accepted as an actor alias. A recipient's claim remains per-observer, never another observer's true-name evidence.
- A monotonic per-actor session-generation and appearance-epoch projection fences old claimed beliefs; advancing appearance invalidates other observers' earlier claims. A committed tombstone clears any observer knowledge *of* or *by* the retired canonical actor. Future claims referencing that actor fail in the same journal lineage, including after restart. Repeated event ID and identical payload return the original historical receipt; duplicate event ID with altered target, generation, name or kind is rejected. Historical receipt is NOT current observable knowledge.
- A **proposed external anti-rollback hook** `open_with_minimum_head(path, floor)` rejects any otherwise valid local journal with head below the caller's separately protected high-water. This library does NOT create or cryptographically authenticate that monotonic floor. Plain `open` can accept an older, internally valid snapshot; regression explicitly documents this release blocker. FNV-1a is NOT a MAC, digital signature or a trust anchor. The new local journal also is not encrypted at rest: do not put real personal/private true names or production chat evidence in it.

## Deterministic acceptance

Tests use genuine Core8B `CharacterRecord` typed u128 IDs and current lease registry fixture, never a reused numeric player slot. Five new parent tests: (1) two distinct observer claims, no verification, exact replay after restart and conflicting event ID denial; (2) old lease versus higher actual generation, appearance A→B loss of old claims and stale-epoch rejection after restart; (3) one committed subject tombstone, future resurrection rejection, checksum tamper and sequence gap failure on recovery; (4) valid old prefix can roll back without an external floor, `open_with_minimum_head` denies; (5) **real separate Rust child writer** commits+fsyncs MYID before observer delivery and holds exclusive lock, parent confirms local writer lock denial, SIGKILLs child, then reopens and replays exactly one claim/receipt. An intentionally ignored subprocess helper is invoked by the crash parent.

## HARD production gates

1. **Authentication/authority:** current Core `SessionLeaseRegistry` is an already committed generation fixture in tests; actual production login and global/distributed epoch fencing are NOT present. An untrusted caller can still propose an arbitrary appearance epoch and chosen listener; Core8C+Physics must provide complete completed-tick LOS/witness/provenance and reserve trusted actor epochs before any bridge→journal integration.
2. **Privacy:** Secure private true names, aliases, role-restricted moderator audit, encryption/key custody, retention and revocation policy need a separate review and store. The existing dormant `IdentityRegistry` is still in-memory for Verified witnesses; this WAL deliberately persists **no Verified evidence**, no private controller-kind, no account credentials and no public true names.
3. **Recovery:** External non-replayable high-water/lineage+authority epoch and protected signature/MAC or trusted volume are missing. It must survive an older **entire valid** checkpoint, independent-host split brain, lost ACK, duplicate evidence ID, role revocation, appearance ABA, schema V1↔future-V2 migration with rollback. Do not treat the file checksum or user-submitted provenance as authority.
4. **Transport:** 8A must deliver only viewer-specific obscured projections bound to a current authenticated viewer lease; 8C/Physics must attest trustworthy evidence, LOS, completed tick and appearance change; NPCs must allocate stable canonical Sentinel identities. Main #360 controls one durable identity authority, integration and GO; no concurrent second owner.
5. **First playable:** This optional IDR slice must not delay four real browser players, four rack swords and physical combat. The original Core↔Items dual-writer sword split-brain hard-stop remains independent in #629. No main merge, no migration, no launch or deployment.

This is a **tested dormant durability building block**, NOT a full trusted identity and disguise system.
