## Why the live v1 34-byte input cannot meet the release contract

Legacy v1 INPUT has a 16-byte header and 1–3 six-byte samples, each using all eight available button bits. The currently merged browser still initiates a normal left-mouse light at pointerUP; the Combat4 #700 partial server correction fixes held-clock reset and late double-hit but does not activate pointerDOWN instantaneous windup. Press and release can occur between two 30/60Hz input snapshots and disappear, and a lost preceding LMB-held packet leaves a binary sample with attack=0,heavy=1 indistinguishable from a standalone KeyE heavy. There is no session-epoch-scoped original gesture identity, authenticated typed source, or ACKed event chronology. Guessing by wall clock/HP/input window would reduce the original server authority.

## Dormant proof-of-contract packet (not allocated in live protocol)

Review-only JS source: tests/fixtures/core8c-lmb-gesture-wire-review.mjs. Pure Rust test-only decoder: server/tests/prealpha_gesture_wire_review.rs. Shared golden vector and negative fixtures: tests/prealpha-gesture-wire-review.test.mjs. **Lives exclusively under tests/fixtures, which the original immutable Pre-Alpha distribution excludes. Not imported by online-game.mjs, server/src/lib.rs, main.rs, Chat C1, runtime or packager.**

Proposed header, exactly 16 bytes: version=2 (u8), tentative type=0x52 (u8), count=1..4 (u8), reserved=0, server-issued actor-session epoch (u64 little-endian), packet sequence (u32 little-endian).

Up to four separately represented events, exactly 16 bytes each: event sequence (u32 LE), gesture ID (u32 LE), capture client tick (u32 LE), typed kind (u8), authenticated-source *claim* (u8, bound to session by future server), reserved=0 (u16). Kinds: LMB_PRESS=1; LMB_UPGRADE=2; LMB_RELEASE=3; LMB_CANCEL=4; KEYE_PRESS=5; KEYE_RELEASE=6. Source is 1 for all LMB kinds and 2 for KeyE. The actual authenticated QUIC session, NOT an untrusted packet source field or the epoch alone, must own all capability. No client-chosen hit, damage, readiness or action authority.

The shared immutable **48-byte** Rust and JS golden vector includes a LMB_PRESS and LMB_RELEASE at the **same clientTick=100** but with distinct event sequence IDs 1 and 2. A legitimate quick click is no longer silently erased by boolean sampling. A pure, dormant JS state model rejects gaps unless retransmitted, re-enveloping duplicates, old gesture IDs, a mismatched release, and a prior-session epoch. It distinguishes standalone KeyE from a mouse release. Actual original live v1 Rust and JS INPUT decoders are tested to REJECT the proposed version-2 envelope (no runtime route or accidental compatibility). Both preview parsers reject invalid header versions, event types, source/gesture disagreement, reserved bits, zero IDs and malformed lengths. The Rust test does not modify World or Combat and is not included in the executable server.

## Non-negotiable missing implementation — REQUIRE Main/Core/Combat decision

1. **Actual negotiated packet type and capability** must be approved before production; this unused tentative version/type is intentionally rejected by the v1 live decoder. Server must generate and tie epoch to the admitted QUIC actor lease, rotate it on reconnect, and reject all events after death/respawn epochs as appropriate. Epoch is an anti-mixup label, NOT a secret credential or security boundary on its own.
2. **Actual EVENT_ACK and retransmission** must be added before networking. The pure preview gate only models contiguous in-order acceptance and *requires* a resend of missing events; it has no outbound ACK, bounded reorder buffer, rate limiter, production ingress cap, or cryptographic integrity. No claim of guaranteed delivery under WAN loss.
3. **Combat4 must consume real events authoritatively:** first valid PRESS starts normal light windup; matching still-unlanded upgrade retains original server elapsed windup toward heavy READY after 320ms; matching release fires a single heavy only if server READY; early release resolves no more than one legal light; CANCEL never attacks; a late upgrade/duplicate release cannot attack twice; standalone KeyE must remain distinct. All time, stamina, damage, target, arc and cooldown decisions stay exclusively server-owned.
4. **Native and live-server qualification** must demonstrate instant down, very short same-sample tap, packet loss/reorder, event ACK resend, low-latency light, late/lost hold, death/respawn/reconnect, focus cancellation, Space+LMB, RMB+LMB, wheel parry/roll, no repeated action, and the unchanged strict M41/M107/M108/M147/M155/M171/M194/M206 tests. No protected assertions relaxed, no guessing from client clocks.
5. Original Pre-Alpha Chat C1 is off-by-default and unaffected. No new feature enabled, no source rollout, main merge, operator staging, public websocket or extra listen address, service restart, or promotion from this draft.

**Conclusion:** This is a tested cross-language *proposal* identifying a feasible typed-event envelope and its failure modes, not implementation of the owner-approved instant-light control. Main must approve a negotiated transport design and Combat4 must implement and qualify the real gameplay before Pre-Alpha GO.
