# M221 — actual Firefox wheel-event attestation for M34 W3C timing

Issue #263 tracks a real guard-break acceptance failure: in first M220 exact-head CI, Firefox W3C wheel HTTP ACK took 128.8ms; Chrome attack waited for ACK and hit 284ms after the wheel beyond the unchanged 240ms block interval. Defender lost 34HP; CI correctly failed. Earlier M212 timing had also proven removing the ACK gate naively could create premature 125ms parries.

M221 is a test-only alternative: the actual trusted DOM Firefox wheel-back event posts a one-time challenge receipt to the localhost-only flight server. Only one positive-delta native wheel event with isTrusted true and the exact active challenge is accepted. After browser delivery and the original 48ms lead, the helper sends exactly one Chrome W3C down/up pair. The Firefox W3C command ACK remains mandatory for final successful result; missing/late/untrusted receipts are fatal. No synthetic input or direct authoritative-state write. Original 100HP, guarded three -38 impacts, zero parries, 125ms parry, 240ms block and all game rules remain untouched. New behavior requires exact-head cross-browser CI and independent merged-main quality before any merge. No playable or production deployment.
