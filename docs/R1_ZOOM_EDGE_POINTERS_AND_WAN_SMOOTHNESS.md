# R1 — wider arena, directional off-screen opponents, smoother WAN rendering

## User-facing changes
- Zoom the **online authoritative render layer** to 84% of previous fighter/presentation size. It exposes ~19% more horizontal and vertical world distance, without modifying the 960×540 canvas, mouse aim, movement speed, attack reach, collision, combat radius, ticks or QUIC packets.
- Add tiny gold triangular pointers near each screen edge **only** for opponents outside the visible canvas who are still within 1,200 world units (maximum 5 nearest). The arrows point to their true camera-relative direction with an inset from the clipping edge and a small #ID label. Dead actors, the local fighter, malformed positions, and far-away interests are ignored. Unlike red threat markers, these pointers are purely informational.
- HUD, aim, score, minimap-free edge indicators and attack warnings remain in screen-space. Only visual fighters and world combat effects use the zoom. World positions themselves are unchanged.
- Avoid repeated per-frame remote sprite allocations: reuse the existing interpolator's scratch per net ID for edge-pointer locations.

## Network movement improvement
Live R1 smoke from external X230i recorded 321–325ms input→ACK p50 and 92–125ms ACK jitter p95; subsequent ICMP pings varied 144–481ms (average 304ms). These are client-to-VPS observations, not universal player latency, and routing remains an independent problem.

The server already sends 20Hz snapshots while browser presentation advances at ~60Hz. Under large WAN jitter bursts, the old render clock could jump many server ticks in one requestAnimationFrame when a late snapshot arrived, visually teleporting remote fighters. The new render-only clock limits individual catch-up frames to 145% of elapsed frame time (with an independent 50ms cap), never going backwards. It converges toward the same existing target and preserves the 90ms interpolation baseline, 100ms maximum extrapolation, and wrap/visibility reset behavior. No changes to authoritative own player position, reconciliation, WebTransport, packet format, combat, stamina, speed, movement, or hitboxes. Optional netstats shows bounded catch-up count so the effect can be measured.

## Release acceptance
Focused unit and CI tests cover four directional edges, diagonal clipping, near/far/death filtering, number cap, render/HUD isolation, target-clock burst bounds and teleport/outage handling. Still require the full main-equivalent Rust/Chrome/Firefox/512-player quality suite and external live smoke. Keep previous release rollback until client tests pass. **Do not confuse reduced visual snapping with lower actual network RTT**; routing/ACK latency remains tracked in #293.


## M46/M47 full-resolution remote vitals and identity
The first exact-head quality rerun passed 127 checks (including unchanged M147 FFA punish) but M46 spatial vitals failed: reducing the entire drawing context to 84% shrank the ordinary 42px green guard bar to ~34 pixels, below the original strict full-size readability check. The observed red 22/green 34 ratio already represented the *correct* authoritative 66/100 damage. The fix moves remote health bars and identity badges to a separate **unscaled screen-space pass**, centered at the same zoom-projected enemy positions. The remote sprite/world combat and attack tells remain zoomed; full-resolution UI stays 42px wide, player labels 34px. M46/M47 tests and thresholds are unchanged. Never fake health or change server combat state. This also improves actual readability at the wider camera scale.

## Directional light under late browser key release
The strict M121 short-LMB + W-strafe browser test intermittently produced an *authoritatively ordinary* 34HP light strike rather than the intended directional sweep when simultaneous trusted keyboard/pointer input straddled a frame. We now preserve the genuinely held movement direction at LMB pointerDOWN for the duration of that one light gesture. Its real release movement wins when present; the press sample is used only if release movement has become neutral (e.g. KeyW keyup ran before pointerUp). Jump attacks, heavy charges, run behavior, attack strength and server authority remain unchanged. Pointer cancellation, blur and completed gestures clear this state so it never leaks into later attacks.

## M145 three-player recovery handoff observation
The exact-head browser quality reached 82 successful gates before M145 observed two **genuine** consecutive target modes, `PUNISH TARGET #3` then `PUNISH TARGET #1`, but captured the final frame while #1 was *still* in authoritative jump-attack recovery (M233 trace showed the remaining target enter idle ~100ms after that read). The M145 read-only sampler was capped at 760ms from the concurrent attack start, too short under slow WebDriver scheduling for both sequential recovery windows to finish. Extend **observation only** to the already established 1250ms M144 duration. Keep all three mandatory target transitions, W3C keyboard/pointer input, exact 70..150ms M145 input-lead, 100HP/guard, server 60Hz lifecycle and >24px spatial tell proof unchanged.

## M246: Short-LMB release headroom for true dual knockdown punish
Post-merge CI intermittently missed the strict M209 60Hz overlap of **both** real 260ms knockdowns because the M159 acceptance flight waited 40ms between two already-trusted native W3C pointerDown/Up requests. R1 light attacks begin their 135ms windup on **release**, and under browser-driver scheduling this ate ~2 ticks from the shared 16-tick punish window. Shorten only that hold to 5ms (matching the previously successful M156 genuine short-click setup). Preserve the real W3C pointerDOWN/UP, pre-aim and re-aim, all actual server-tick 260ms overlap, exact 34HP selected hit, untargeted 100HP/guard, roll provenance, recovery order and original test thresholds. This is CI input choreography: **not** a game rule change, packet shortcut, server leniency or widened punish window.
